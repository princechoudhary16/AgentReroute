# Live AgentRx / AgentReroute comparison UI

User authorized starting the existing UI and adding a page comparing both algorithms and their performance. User explicitly selected actual Ollama executions. Extend the existing Python stdlib/HTML UI; no new frontend framework, hosted model, or trained checkpoint is required.

## User-visible behavior

Keep the current propagation view at `/`; add navigation to `/compare`. Comparison has two execution columns, AgentRx and AgentReroute, analyzing the same recorded scenario. User selects an installed Ollama model and one of the four bundled scenarios, then starts a job. Display live model stages, perspective names, checks and violations, ranked candidates, repair directives/replay trace, verification, elapsed time, model calls and token usage. Provide a shared event cursor with play/pause/previous/next so the two algorithms can be inspected together; live execution and recorded playback are separate controls. Preserve prior results while viewing event history. Status/error text stays visible; never fabricate missing measurements.

Model inference is real. Input MAS trace and user simulator remain controlled scripted fixtures, clearly labeled. Use actual Ollama for both diagnosis and post-rollback agent turns; the same repair engine, retail backend and budgets serve both systems. Run systems sequentially to avoid shared local GPU contention and label that timing includes model loading/queueing. Single-scenario observations are not benchmark accuracy or calibration. Initial AgentReroute weights are explicitly labeled untrained. Do not display documentation's unverified 71.4% figure.

## Backend

New `demo/comparison.py` owns a bounded in-process job service, model discovery (fixed local Ollama endpoint), provider instrumentation, same-input scenario construction, actual algorithm calls, shared recovery and post-policy scoring. New `demo/comparison_page.py` owns the standalone page template. Existing `demo/visualizer.py` registers routes and navigation.

Routes: GET `/compare`, GET `/api/models`, POST `/api/comparisons`, GET `/api/comparisons/<id>?after=<event-seq>`, POST `/api/comparisons/<id>/cancel`. JSON POST with same-origin validation. Restrict models to locally installed names and scenarios to the catalog. Reject duplicate active jobs; retain at most eight completed jobs. No arbitrary filesystem paths, endpoints, code or credentials accepted from the browser. Save request/response, diagnosis, replay and comparison artifacts under `runs/ui-comparisons/<uuid>/`. Validate lengths, payload shape and request size. Limit model calls per system; cancellation applies after the current call and prevents subsequent inference. Service close cancels outstanding work; workers are daemon threads. Model/server errors are distinct from abstention; one failed side must not become a successful result or prevent the other side from executing, unless canceled.

AgentRx calls the real `diagnose` with evidence/checklist enabled, joint judging and oneshot generation (shown in UI). AgentReroute calls the real `diagnose_mp_rl` with evidence enabled and its auxiliary window-repair disabled; keep a fresh `DualLoopRLJudge` for ranking. Convert outputs to benchmark hypotheses and use the same `RepairStrategyPolicy` for both. Apply the existing observable no-fault abstention test on the MP side. Post-rollback agent calls use native Ollama; pre-rollback requests use the controlled original workflow and the user simulator stays scripted. Score actual retail state only after the policy returns. Record MP feedback through the same observable acceptance/termination checks as the existing cross-branch integration. Do not read injected-fault records or gold outputs in model inputs, ranking, repair proposals or RL rewards. Viewer-only reference injection and task score may be computed afterward.

Instrumentation sends a request-start event, then completion/error with measured timing, telemetry and response. Missing telemetry stays null. Each side has its own provider and output folder. Checker summaries distinguish SAT/VIOL/SKIP/ERROR and seeds versus LLM checks. Errors swallowed by existing MP synthesis remain visible in the request log; partial-seed fallback is explicitly shown. Persist final result plus the event log; UI can recover a still-running job on page refresh via sessionStorage. No calibrated-probability claims.
